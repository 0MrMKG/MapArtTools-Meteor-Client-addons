# Builder Toolbox

A client-side Meteor Client addon for Minecraft 1.21.11.

Release **5.0** improves placement confirmation, wide-area repair and checkpoint reconciliation, adds outward/return-pair supply planning in Full Mode, and includes inventory recovery, control ownership and persistent progress fixes. The distribution JAR is `build/libs/builder_toolbox-5.0.jar`.

## Features

The five menu modules appear in this order:

1. **Map Art Maker（Once）** — print the currently loaded flat Litematica projection with snake walking and restocking.
2. **Map Art Maker（Full Mode）** — make a directory batch of map art, including clearing, printing, map locking and product storage.
3. **Underfoot Scaffold** — place solid hotbar blocks under or just ahead of the player while the player walks.
4. **Chest Organizer** — move misplaced items into matching labeled storage or the registered overflow chest.
5. **Auto Craft** — convert bones to bone meal and bone blocks, then return products to their original storage.

The Builder Toolbox category reapplies this order after Meteor's alphabetical sorting; other categories keep their normal ordering.

**Schematic Printer** is no longer a registered module or independent switch. `LitematicaPrinterModule` remains as the ordinary map-art worker's private internal placement instance; its placement algorithm is retained. Full Mode continues to use its separate `FullAutoPlacementEngine`.

## Requirements

- Java 21 JDK
- Fabric Loader 0.18.2 or newer
- Meteor Client for Minecraft 1.21.11

## Development

Open this directory as a Gradle project in IntelliJ IDEA, then run the `Minecraft Client` run configuration to test the addon.

Build a distributable JAR on Windows with:

```powershell
.\gradlew.bat build
```

The built JAR is written to `build/libs`. Install it in the same `mods` folder as Meteor Client.

`build` and `check` also execute the standalone regression suite. Run only that suite with `gradlew regressionTest`.

Map Art Maker（Once）, Map Art Maker（Full Mode）, Chest Organizer and Auto Craft share movement/container ownership: stop the running task before starting another. Selection mode respects the same ownership. Both placement engines ignore offhand-only matches and use atomic hotbar swaps; full-backpack cursor recovery may return materials only to its owned matching storage, or use existing hotbar materials for a bounded attempt to create space. If no safe space can be created, the item is retained and the status explicitly asks for one free slot.

Ordinary map-art completion now requires server block observations for attempted cells, rather than client prediction alone. Full-auto inspection preserves observations when already-visited chunks unload during the same pass. After a restart it clears stale observations and continues from the saved next waypoint, wrapping around to recheck a complete fresh pass. Empty-map hotbar transfers save both slot intents and reopen the supply box for authoritative confirmation before changing map ownership. Chest Organizer also persists confirmed cargo and outstanding transfers, and waits for complete server inventories before scanning or committing a transfer.

## Map Art Maker（Full Mode）

**Map Art Maker（Full Mode）** is a separate top-level module in **Builder Toolbox**, alongside **Map Art Maker（Once）**. Their persistent internal names remain `map-artmaker-all-auto` and `Map Art Maker`, respectively, preserving saved settings and keybind compatibility. Once is a display label: the ordinary worker still repairs until every required target matches, rather than stopping after one sweep. `map-artmaker-all-auto` is no longer the displayed menu title. Full Mode has its own switch, settings, worker, placement engine and helpers; it is not a setting or sub-feature of Once. It does not call the ordinary map-art worker or its private placement instance. Changes requested for both map-art modules are implemented in each independent worker.

In **Full Auto Batch**, enter a **Schematic Folder** relative to Litematica's actual `schematics` directory (for example `pictures`). This is a text field and accepts **Ctrl+V**. **Validate / Reinitialize** in **Schematic Directory Validation** stops the current run and reads the directory's direct `.litematic` files asynchronously, reporting their count, resolved path and first five naturally sorted names. Every successful check of a nonempty directory archives and resets the batch, **even when the directory and files are unchanged**. Registered locations, supply boxes and settings are retained; enable the module afterward to start again from picture 1. The button does not operate the lever, start printing or modify projections. Failed/empty checks, changed settings or game context during a check, and unsafe/unconfirmed map transactions preserve the old checkpoint instead. This checks file access, not blueprint dimensions or map alignment; those are validated when the batch starts. The direct `.litematic` files are snapshotted in natural filename order; nested directories are not scanned. Supported blueprints are one 128x128 layer at relative Y=0. Native Litematica region offsets and negative sizes are preserved, with no rotation, mirroring or automatic recentering. The target bounds must align with a scale-0 map: minimum X and Z are each `128*n - 64`.

Use **Set Canvas Origin**, **Set Clear Lever**, **Set Map Supply**, **Set Cartography Table**, and **Set Product Storage**. Settings hide during selection; right-click to record, Esc returns. The canvas origin is the clicked block's X/Z and Y+1. Other positions are the clicked block itself. Selected positions have yellow outlines only in selection mode. Map supply/product storage accept chests, barrels and shulker boxes without labels; the original labeled **Select Supply Chests** remains responsible for printing colors.

Chinese folder and blueprint names are supported, including spaces. For a file at `schematics/地图画/风景合集/风景2.litematic`, enter only `地图画/风景合集` in **Schematic Folder**, not an absolute path or a second `schematics/` prefix. Relative paths use Litematica's actual configured schematics directory, not this addon's source directory. Checkpoints preserve Chinese paths and filenames.

Enabling **Map Art Maker（Full Mode）** automatically starts or resumes the saved batch and executes each picture as: validate file -> lever on 20s/off 20s/on 20s/off 20s -> wait another 10s without inspecting the cleanup result -> first snake printing sweep -> second, reverse snake sweep that repairs and checks together -> keep alternating repair/check sweeps until the missing-block threshold is met -> fetch exactly one empty map and one ordinary glass pane -> activate at the canvas center and hold for approximately 2s -> lock at the cartography table -> confirm the locked map's actual ID in product storage -> next file. These are exactly two dispenser triggers: one dispenses water, the other retrieves it. There is no post-clean scan or automatic repeat flushing. Printing no longer stops at band boundaries for a full-canvas check, and there is no separate inspection-only walk or artificial repair-pass delay.

Full Mode's **Allowed Missing Blocks** defaults to **0**, accepts **0..16384**, and uses an inclusive comparison: the missing count must be **<=** the configured value. Only non-air blueprint targets whose actual world cells are air or replaceable count as missing; water and grass occupants also count as missing. Excluded colors do not count. Occupied wrong blocks are reported and marked red but are not included in this threshold or automatically broken. Any unread cells still prevent passing. The second sweep repairs reachable missing cells and replenishes available colors while recording the world; if it does not pass, a forward sweep follows, then reverse again as needed. There is no fixed sweep limit or forced map creation after sweep three. Each pass retries needed supplies. You may adjust the setting while running or resume directly after changing it; it is excluded from the batch configuration signature, requires no reset or canvas clearing, and does not roll an already-started map-material/activation/cartography/deposit transaction back to printing.

A resumed repair sweep preserves its saved next waypoint and pass number but clears offline observations, continues the remaining route and wraps around to obtain fresh observations. During the same uninterrupted pass, observations from already-visited chunks remain valid after unloading. The center capture does not wait for complete pixel updates or walk an extra capture route. Two inventory slots are reserved for map materials during printing and repair restocking. Before the first cleanup pulse, the canvas must be loaded with a solid foundation, two inventory slots must be empty, and any required color not already stocked in sufficient quantity needs a registered supply box.

Checkpoints are atomically saved in `config/builder_toolbox/fullauto-batch.properties` with world/dimension, all five locations, configuration, file hashes, phase, lever intents and map IDs. Ordinary enabling still resumes progress; only explicit **Validate / Reinitialize** or **Reset Batch** requests a new batch. Resume validates every snapshotted file before interaction; newly added files wait for a new batch. Restarting while printing rescans the world and continues without clearing. Deposits are checked by reopening product storage; uncertain/lost map ownership pauses rather than producing a duplicate or clearing the next image. Locking can change the map ID. A resumed lever wait uses its saved remaining duration (legacy checkpoints conservatively restart the wait); an unconfirmed lever edge inconsistent with the actual block requires inspection. Reinitialization archives the checkpoint as `.previous` and preserves older archives in unique `.bak` files; archive/save failures retain the live checkpoint. Location/directory/enabled-filter changes require restoring the checkpoint's configuration or resetting the batch. Storage, lever and table need normal walkable floor connections at canvas height. Esc/background operation remains supported.

The original mode has priority on the same client: Full Auto refuses to start while the original is active; enabling the original while Full Auto is running stops only Full Auto first. This prevents both workers from competing for player controls, inventory or pause settings without changing the original module's implementation.

Full-auto **checkpoint continuation is always enabled**, with no extra toggle or Start / Resume button. The atomic disk journal also saves the restocking phase, inspection matrix/route cursor, remaining timed waits and cumulative batch runtime (offline time excluded). All phases checkpoint about every two seconds and on orderly shutdown; critical operation intents and confirmations save immediately. A forced process termination can lose work since the last checkpoint, so recovery always reconciles actual world and inventory state instead of replaying old clicks. Printing checkpoints save the exact snake route/cursor, fixed starting reference, band width/direction, verification pass and work return position at waypoint changes, approximately every two seconds, and when stopped. After leaving the game or restarting the client, re-enable **Map Art Maker（Full Mode）** to validate the same world/configuration/files, rescan actual blocks, return to the saved working position and continue without clearing. Supply-trip checkpoints retain the work position rather than the chest location; inventory and supply decisions are recalculated live. A saved restocking phase completes the outstanding band demand before returning, rather than walking back prematurely. If width/direction changed, rebuild the remaining route with the new parameters. Older checkpoints without a cursor still continue by rebuilding from actual blocks. Do not use **Reset Batch** when intending to continue. The module remains disabled on disconnect until explicitly re-enabled; continuation does not automatically operate the player immediately on login.

## Inventory handling

### Full Mode: accurate bands, paired supplies and sparse repair

Full Mode keeps a fixed outward/return pair of snake bands. Each band entry checks its own material deficits once; during travel a nearby exhausted color can trigger resupply even when other colors remain in the bag. Only obtainable colors with available capacity trigger that trip. Supply demand still combines both bands' actual remaining cells, subtracts current inventory, and reserves space for return-leg colors before allocating extra stacks to a large outward-leg patch. The current leg leads quota allocation, but box selection is nearest-first across all still-needed colors; neither an empty inventory color nor a preferred color overrides distance. Later pairs cannot crowd out that stock. Capacity limits and unavailable boxes may still require additional trips; missing cells remain in the matrix. Completing a pair no longer rewinds its entire route for deferred holes. Normal supply travel remains movement-only, with two map-material slots reserved. Once retains its own existing supply policy.

Each Full Mode supply trip freezes its initial capacity-limited quotas. Remaining world demand can reduce them but taking a stack cannot enlarge them. Visits persist across color selections, even if a box's cooldown expires during travel. The current nearby box is used until its quota is met or its contents/capacity/access prevent another transfer; a second same-color box is not visited just because the first stack was taken. Once no eligible unvisited source remains, the worker returns to printing. A new supply trip recalculates inventory and can reuse those productive boxes. Newly opened supply containers wait for their matching full server inventory and two settling ticks before any empty-box decision; synchronization timeout is an access failure, not empty stock. This trip bookkeeping is runtime-only and recalculated after a client restart.

The first two bands receive one additional preparation check before entering the starting point, even when some colors are already held. These are the first distinct bands in actual travel order, so Reverse prepares the far-end pair. If the bag has no carpet capacity, the worker retains an opening-pair shortage marker while consuming usable inventory. A newly free slot or newly usable opening material prioritizes a return to those holes rather than postponing them to the final review. A stable full bag does not repeatedly start the same failed supply trip. Startup logging reports direction, band numbers, required/held material coverage and usable empty slots. It does not automatically unload unrelated items.

Like Once, all bands now follow one continuous centerline sweep, including the physical first and last bands. The former one/two-column boundary repair stops are removed. Reachable cells are filled before moving, with outer rows prioritized on perimeter bands. Endpoint repairs stay within a fixed local area anchored when finishing begins; they cannot creep backward across the whole band. The final underfoot cell can use an adjacent safe stand. A blocked entry can approach from a nearby supported position. Unavailable materials or exhausted placement attempts remain explicitly missing for the final inspection. Forward and Reverse use the same rule and saved route format.

Band entry uses precise center alignment before printing, rather than the chest endpoint's 0.6-block arrival tolerance. Width-setting changes rebuild the route and logging reports the actual width. Complete five-row bands have centerlines five blocks apart; a 128-row canvas ends with a three-row partial band whose centerline is four blocks from the previous one. This edge case is intentional centering, not a four-row full-band plan.

Carpet-edge recovery tracks actual displacement independently of placement confirmations. After 12 commanded walking ticks without meaningful movement at a carpet transition (20 on other ground), navigation releases forward for three ticks before a bounded safe side-step. Small oscillations do not reset this counter, placement waits do not accumulate it, and nearby printing cannot interrupt an active escape. Escape attempts consume the route retry budget instead of repeating indefinitely. No sprinting or jumping is added.

Full Mode uses Once's bounded stationary pipeline of up to three pending placements. Actual rotation callbacks stay serialized; movement waits for confirmations. It revalidates the held item, target destination, ray hit and reach before a delayed click. On bare glass or other bare floor, forward carpets in the walking corridor are deferred until the player passes them; side rows still fill normally, and endpoint repair can finish the last center cell. Rejected cells remain missing. After the main sweep, one coverage inspection finds holes and repairs them, fetching obtainable missing materials immediately and returning to the saved repair position. Failed repairs retain the existing coverage matrix for further targeted attempts instead of resetting it for another physical lap. Unread areas alone may need additional loading travel. Broad repair reads only the current 128x128 canvas, at most 1024 cells per tick with a time-budget check every 32 cells (approximately 1.5ms budget, not a hard real-time guarantee). Background reconciliation of loaded blocks continues after placement updates; completion still requires a fresh scan, the configured missing limit, no unread cells and no outstanding placement.

On printing resume, a wide patrol checks the earlier bands up to the saved band, including bands previously omitted as complete. The worker rebuilds the remaining route from actual observations instead of trusting the old cursor. Repair-resume discards offline observations and uses the same broad scan; saved narrow routes are migrated. These rules supersede the older saved-waypoint/full dense repair traversal description above. Ground travel and workstation travel attempt bounded adjacent safe-ground movement when stuck, without sprinting or jumping.

Supply travel is **movement-only in both directions**. Returning from a chest cannot place blocks or consume the materials planned for the next snake band. At a route endpoint, arrival allows up to 0.6 blocks of horizontal distance while still requiring real walkable ground, grounded state and compatible height. Intermediate grid corners keep their 0.2-block precision. Persistent unstable carpet-edge placement waits trigger a safe adjacent-ground reposition instead of waiting forever; no sprint, flight or teleport is used.

Failed/unreachable supply boxes have a separate 60-second access cooldown and are not reported as empty. The bot tries another same-item box or continues another stocked snake band; unavailable supplies are automatically revisited during normal printing. An exhausted path without an arrived endpoint is replanned or rejected, never left as a movement-free MOVING state. Normal Map Art Maker（Once） still requires its full projection matrix to match and retains its repair behavior. Full Auto instead uses the configurable missing-block policy above: each repair pass tries a selected missing color at most once across its registered boxes, and exhausted colors or insufficient inventory space yield back to the repair route rather than creating an endless supply wait. Later alternating passes retry supplies and continue until the actual missing count is within **Allowed Missing Blocks** and no unread cells remain. Wrong blocks remain marked, are excluded from this threshold and are never automatically broken. This Full Mode setting does not change Once's exact-completion rule.

Both map-art modules have their own **Auto Eat** setting, enabled by default. Below four hunger icons (less than 8/20 points), the worker waits for outstanding placement/stock operations, stops moving and consumes food from the hotbar or main inventory until hunger reaches 20/20, then resumes. Main-inventory food uses an atomic hotbar SWAP rather than cursor-based sorting; the original selected slot and displaced stack are restored when safe. Food use is directed into the air so it cannot open the dispenser under the crosshair. Registration, idle/paused states and critical map activation/cartography/product transactions are not interrupted. Chorus fruit and clearly harmful foods are excluded. Missing food or rejected consumption produces a warning, releases the use key and yields back to the job with a 10-second retry cooldown rather than hanging indefinitely. Switching the feature/module off or leaving the world releases only its owned input. Background/Esc operation is supported; actual server consumption still requires in-game testing.

Both **Map Art Maker（Once）** and **Map Art Maker（Full Mode）** restock directly from the current inventory contents and actual available capacity. They no longer sort or merge inventory stacks before a supply trip. A full inventory is handled by the existing print/capacity logic, not cursor-based rearrangement. A cursor stack no longer switches either map-art worker to PAUSED. The worker returns it to a remembered source slot or a compatible/empty player slot and resumes after a brief settling period. It does not drop items or swap unrelated stacks; if no valid slot exists it retains the item and retries automatically when space is available. Manual unrelated containers are left alone. Full-auto hand selection uses one SWAP operation rather than cursor-based movement.

Full-auto cursor recovery also handles interrupted walking/printing: ordinary carpets can be safely parked in an empty/compatible offhand slot, but round-owned maps and glass panes cannot. In an owned material chest, an accepted whole hotbar stack can be returned to an empty storage slot to make room; this never exchanges unrelated stacks. If the player handler is full, recovery can walk on real ground to usable missing cells, consume an eligible hotbar stack and return to the saved work position before resuming the snake. The planner no longer assumes three placements can empty a full stack; failed attempts and unusable stands are bounded. Server cursor corrections are reconciled, while matching vanilla predictions need no explicit acknowledgement packet. The full-auto placement engine does not send redundant close-screen packets after placing: vanilla can otherwise close a server inventory and return/drop its cursor independently of the client's visible screen. Pending acknowledged own containers are claimed before the cursor gate, and ownership is retained when an interrupted screen cannot yet close safely. If no compatible inventory/offhand/storage destination or reachable material-consuming work exists, contents remain held and a specific space warning is shown rather than dropping items or claiming recovery succeeded.

Supply access has a 30-second no-progress watchdog: if neither approaching the selected box nor receiving materials advances, the worker skips that box and tries the next registered same-item box. Opening is limited to three actual interaction clicks, not three waiting ticks. Transfer acknowledgement retries remain bounded; unavailable stock and inventory capacity retain explicit status messages instead of silently clicking forever. This is fault handling, not a guarantee against every server or movement failure.

## Auto Craft

The initial recipe chain is **Bone -> Bone Meal -> Bone Block**. In Auto Craft settings, enable **Select Storage Blocks**, right-click each chest, barrel or shulker box, then press Esc. Enable **Select Crafting Table**, right-click the table, then press Esc. Positions are saved; selected storage blocks have yellow outlines and the table has a cyan outline during selection. Labels are not required.

Move preexisting bones, bone meal and bone blocks out of your inventory and leave at least four empty slots. Enable the module or press **Start / Resume**, then close the settings screen. It walks on real floor to each source and the crafting table, processes one source at a time, and returns blocks and final leftover powder to that source. Depending on free inventory space, each trip takes up to three stacks of bones (192 bones produce 64 blocks). Locations must have a walkable route on the player's starting floor. Full storage, unavailable interaction or an unconfirmed inventory operation pauses the job with its materials retained. Free the original storage and press **Start / Resume** to retry. Turning the module off releases its movement key and closes only its own container; a stopped job can resume within the same game session.

## Project layout

- `src/main/java/com/buildertoolbox/BuilderToolboxAddon.java` is the Meteor addon entry point and category registration point.
- `src/main/resources/fabric.mod.json` defines the Fabric and Meteor metadata.
- `gradle/libs.versions.toml` pins Minecraft, Yarn mappings, Fabric Loader, Java, Loom, and Meteor versions.

The project is initialized from the official [Meteor Addon Template](https://github.com/MeteorDevelopment/meteor-addon-template), then adjusted for Minecraft 1.21.11.
